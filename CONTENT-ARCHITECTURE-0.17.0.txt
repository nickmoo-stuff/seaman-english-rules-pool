SEAMEN POOL CONTENT ARCHITECTURE — 0.17.0 / BUILD 1523

Purpose
-------
This build introduces the chapter/content catalogue foundation without changing the
intended Chapter 1 gameplay. The locked 0.16.1 / build 1522 package remains untouched.

Added in this phase
-------------------
- CHAPTERS catalogue with Chapter 1 (Captain Blackball's Domain).
- Stable pirate IDs: dave, simon, holly, mick, blackball, cyclops, vaper.
- Pirate metadata for chapter, chapter position, campaign role and difficulty.
- Lookup helpers by stable ID and legacy numeric level.
- Chapter roster helpers for main and bonus pirates.
- Career schema 5 with chapter completion state.
- Automatic migration: an existing save with all five Chapter 1 pirates defeated is
  recognised as Chapter 1 complete.
- Chapter completion display now reads the chapter state.
- Main release pirate roster is sourced from Chapter 1's catalogue.
- Normal next-opponent progression is sourced from Chapter 1's ordered roster.
- Service-worker cache bumped for the 0.17.0 build.

Compatibility bridge
--------------------
Legacy numeric pirate levels are deliberately retained in this phase. Existing AI,
dialogue, achievements, progression records and 0.16.x saves still understand levels
1–7. The stable IDs/chapter metadata now sit above that system so later 0.17 phases can
move individual subsystems away from numeric identity without a risky big-bang rewrite.

Next architecture phase
-----------------------
Move rewards/cosmetic unlock conditions onto generic data-driven rules, then migrate
remaining pirate reward/trophy mappings away from hard-coded numeric relationships.


BUILD 1524 - PHASE 2: GENERIC REWARDS + UNLOCK RULES
- Cosmetics now carry declarative unlockRule objects.
- Shared unlock resolver supports default, defeat_pirate, complete_chapter, achievement and entitlement rules.
- Pirate reward metadata now lives on each pirate definition instead of numeric cue reward maps.
- Reward summaries and career progress derive cosmetic names from catalogues.
- Legacy numeric career keys remain as compatibility bridge for 0.16.x saves.


PHASE 3 — BUILD 1525
- Cosmetic table/cue cards are now generated from the COSMETICS catalogue.
- Display name, description, preview class, owner/source and dev-only visibility live with each cosmetic definition.
- Static per-cosmetic HTML was removed from index.html.
- Existing appearance and unlock/equip behaviour are intended to remain unchanged.
- Future cue/table additions now need catalogue metadata plus their visual CSS/asset, without hand-writing a new UI card.


BUILD 1526 / PHASE 4
- Pirate roster is generated by CHAPTERS + stable pirate IDs, not data-level numeric buttons.
- Pirate profiles resolve by stable pirate ID and display catalogue-declared rewards.
- Pirate unlock checks accept catalogue unlockRule metadata.
- Temporary Chapter 2 architecture proof added with Pirate McPirateFace and a test cue.
- Pirate McPirateFace is deliberately non-playable and uses an existing portrait placeholder; this is test scaffolding, not final content.
- Removing chapter_2_test, pirate_mcpirateface and mcpirateface_test removes the proof content without changing the framework.

PHASE 5 / BUILD 1527
- Added generic SCENES catalogue and reusable scene player using the existing Blackball story presentation shell.
- Chapter/pirate definitions can reference optional scene IDs; gameplay/progression does not depend on scenes.
- Added Izzy as a stable future-capable bonus-opponent identity and real-photo portrait asset (crop/resize only).
- Temporary Chapter 2 test scene proves image + speaker + dialogue-line + finish-action presentation from catalogue data.

PHASE 5B / BUILD 1528
- Scene definitions now own named asset libraries split into backgrounds, characters and props.
- Dialogue beats select visible layers by asset ID, so artwork-to-scene wiring lives in catalogue data rather than bespoke JavaScript.
- Supports multiple backgrounds per scene and multiple simultaneously visible character/prop layers with percentage-based responsive positioning.
- Character asset IDs can represent alternate poses/expressions; simple frame swapping supports deliberately crude South-Park-style animation.
- Generic cheap motion effects available: shake, bounce, slide and fade. Motion respects prefers-reduced-motion.
- Izzy architecture-test scene exercises background switching, repositioned character layers, props, bounce and shake without changing progression.


PHASE 6 — BUILD 1529: CHAPTER LIFECYCLE
- Career schema 6 adds generic per-chapter lifecycle flags: unlocked, introSeen, bossIntroSeen, endingSeen, completed.
- Chapters now declare unlockRule, scenes (intro/bossIntro/ending), and bonusUnlock metadata.
- Generic helpers determine chapter availability, main-campaign completion, bonus availability, scene completion, and chapter completion.
- Chapter headings expose AVAILABLE / COMPLETE / LOCKED status from lifecycle state.
- Existing Chapter 1 completion is migrated from defeated-pirate data; legacy Blackball scenes remain in place pending the planned pre-1.0 theatre-engine migration.
- Chapter 2 test data includes an ending scene definition so the same scene engine can represent both ends of a chapter.
- This is infrastructure: no real Uncharted Waters story/progression content has been committed.
