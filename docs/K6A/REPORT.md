# K6A — Google Play Billing integration candidate

16 November 2026. Baseline: approved K5A `8228903dbb50f5f3fd6418e872cb5bcf2e55fccd`, K4B content `bd79490`, 0.17.59/build 1589. Candidate: **0.17.60/build 1590**, branch `stage6-k6a-google-play-billing`. The user reports K5B desktop QA 13/13 PASS; no new desktop hardware QA is claimed here.

## Read-only audit

See [AUDIT.md](AUDIT.md), completed before implementation. The repository contains the game and prior bridge/installer sources, not the actual Capacitor Android wrapper. Recorded external versions are Capacitor **8.5.2**, official Google Play Billing **9.1.0**, minimum SDK **24**. The guarded installer verifies the actual installed values when applied. No npm/plugin/library dependency was added or upgraded.

The existing permanent INAPP product/purchase option are **seamen_pool_supporter** / **supporter-buy**. No production identifier or displayed price was invented. Current Play Console state, product availability, tester eligibility, actual application ID/signing/distribution and version-code availability could not be inspected or changed. A real wrapper build and merged/packaged manifest are unverified.

## Implementation

- Reuses the existing Capacitor SeamenBilling bridge, native inventory/acknowledgement state machine and retry JobService. The scoped K6A native update consists of five Java sources, a guarded PowerShell installer and supported-baseline hashes. Historical native patches remain unchanged. The installer recognises K3H.1/new K6A sources, refuses custom/conflicting files, preserves unrelated configuration, backs up and rolls back writes, and is idempotent.
- Queries only the configured one-time product and non-rental option. SDK ProductDetails selection checks INAPP type and a non-empty Play-formatted price; price, ISO currency and micros are returned unchanged. The UI displays Play's formatted regional price and currency when supplied. No subscription, consumable currency or consumption is introduced.
- Keeps native PURCHASED/PENDING/absent/error distinctions; a native-only token and matching package/product are required. Completed purchases are acknowledged then re-queried before access. Retry/coalescing semantics remain bounded and idempotent; never infer ownership from a click, successful flow launch, callback alone, price or imported data.
- Adds an OFF-by-default native debug test policy. Even a future reviewed native opt-in is rejected by non-debuggable/release builds. The actual app flag is read natively; no JS, save, storage or remote-config switch enables payment. The supplied candidate does **not** enable real purchases, debug purchases or production billing. Positive debug-policy and flow tests use mocks. Licence-test account/configuration and separate approval remain prerequisites before changing this gate or attempting device transactions.
- Separates normal query timeout (15 seconds) from interactive purchase wait (330 seconds), aligned with the native five-minute flow bound. Duplicate purchase/restore operations coalesce; controls stay disabled during processing. Background/resume invalidation continues to fence stale ownership, while non-authoritative cancellation/completion feedback survives and queued checks re-query Play.
- Adds persistent understandable purchase-specific feedback: completed, pending, cancelled, failed, unavailable, interrupted and already owned; Processing purchase while the flow is active. Returned-flow/propagation uncertainty stays unverified, including queued resume checks; a short post-flow propagation window cannot be cleared by an immediately absent inventory record. A fresh not-owned query clears old completed/pending hints, including after refund/account change. Restore Purchases reports success only after confirmed ownership. Existing checking/error/no-purchase states and no-scroll message region remain.
- Owner access still unlocks only existing supporter eligibility, including Chapters 1–3 bonuses, Chapter 4 and Wizard subject to their normal progression rules. It awards no wins, trophies, chapters or cosmetic victories. Free Chapters 0–3 work without ownership. Public web/PWA instances never expose a native billing path or alternative gateway. Native ownership ignores developer/imported flags. Existing web developer access/Unlock All Pirates remain separate.
- No approved AI, live physics, Theatre, dialogue, artwork, cosmetics/trophies, save schema or progression/gating logic changes. The preservation audit permits only supporter.js, the Supporter UI function, its restore label, version metadata/cache namespaces, current billing packaging notes and isolated new K6A native files. All other baseline payload bytes are retained.

## Trust model

The explicit approved initial model remains **on-device Google Play inventory**, not server verification. See [SECURITY.md](SECURITY.md) and the design-only [BACKEND-DESIGN.md](BACKEND-DESIGN.md). Client hooks/repackaging, lack of independent receipt signature/Developer API verification, cached Play inventory/refund delays and OS acknowledgement scheduling remain limitations. No backend/domain, service credentials or trusted token ledger exists. No credential is shipped or requested for this local implementation. The design covers a future Developer API/token-ledger/acknowledgement/RTDN/authentication migration without pretending it already exists.

## Remaining external blockers and limits

1. The actual wrapper is outside the repository. Its plugin registration, dependency, versions, signing, application ID and merged/packaged permissions require a local Android Studio build. No Android build/signing keys or substitute wrapper were produced.
2. Real Play product/option availability, licence-test account/distribution and package/signing eligibility are not available to this environment. The source uses the already configured ID; no Console edit or activation was made. Verify these externally before a separately approved non-charging licence test. Do not spend money or change the supplied OFF gate for this milestone.
3. No real purchase, cancellation/pending UI, acknowledgement, refund, reinstall or second-device restoration was exercised against Play. Those paths are mocked; actual account/Play behaviour remains unverified. Same-account restoration is implemented through inventory queries, not proven on hardware.
4. Windows Chrome file:// is blocked by managed Chromium policy and remains NOT TESTED. Mobile checks are Chromium emulation, not physical Pixel/iOS Safari; audible audio, hardware safe areas and actual APK behaviour remain manual checks.
5. Version code **1590** is candidate metadata, not a confirmed available Console upload code. No upload or production activation is authorised. Source mode remains development; normal production builds must retain release-mode web/developer protections and non-debuggable native gating.

## Installation and short QA

Use [native-patches/K6A/README.md](../../native-patches/K6A/README.md) for exact guarded PowerShell commands and rollback.

1. Back up the external wrapper and export a copy of the save. Copy the full candidate `www`, run the existing sync, preview/apply the guarded K6A installer. Preserve all native/signing configuration. Confirm local versionName 0.17.60/versionCode 1590; no Console upload.
2. Gradle Sync/build locally; inspect merged manifest/APK for BILLING, boot permission and protected retry service, correct package and debug/release flags. Install as an update without clearing data. The supplied purchase gate stays OFF; no payment sheet should open.
3. Check saved Chapters 0–4, lesson ticks, trophies, cosmetics, statistics and settings. Check free gameplay while Play is unavailable, plus portrait/short-landscape controls and readable Restore Purchases feedback.
4. Confirm web/PWA makes no Play call; Native/Play failures must not grant paid access or erase progress. Developer test access must not claim a real purchase; imported saves must not restore paid ownership.
5. After a future separately approved licence-test setup, exercise completed/pending/cancelled/error/already-owned, acknowledgement interruption, duplicate taps, refund removal, same-account reinstall and second device. No real-money transactions, release upload or production enablement are part of this delivery.

Reproduction: provide ECJ_JAR, ANDROID_API_JAR, BILLING_AAR and PWSH paths to the real local test artefacts, set writable task-local XDG cache/config/data directories for PowerShell, then run `python tools/run-k6a-qa.py` in the prepared Chromium/Playwright/Python/Pillow environment. Specific filenames select focused reruns. It uses localhost servers/disposable contexts, not real Play. `python tools/package-k6a.py` produces and verifies the full source package from a clean committed K6A branch.
